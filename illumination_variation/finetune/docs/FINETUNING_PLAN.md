#### Stereo pair organization & official split (CORRECTED — verified from LunarDataset & paper)

- Pairs are defined via a **`split.npz` manifest file** (provided with full dataset on Zenodo) containing:
  - `scenes`: list of scene directory names (e.g., `moon_scene_0000`)
  - `images`: list of image prefixes (e.g., `im_00000`)
  - `pairs`: list of tuples `[scene_id, im1_id, im2_id, score]`
- **Three trajectory types**: Nadir, Oblique, Dynamic
- **Official split structure** (from paper & LunarDataset):
  - **Training set**: ~31,000 pairs (split **80% train / 20% val** at the **scene level** to avoid terrain leakage)
  - **Test set**: 3,000 pairs with **interpolated altitudes** (unseen during training)
- The `LunarDataset` class loads the split via `split` argument: `'train'` or `'test'` — it **does not have a 'val' split internally**; validation is carved from training scenes
- Full dataset: 50,000+ pairs, hosted on [Zenodo](https://zenodo.org/records/17514376)

#### Pose convention
- Stored as **camera-to-world** (`cam2world`), 4×4 matrix
- Generated by inverting the world-to-camera (`R_w2c`, `t_w2c`) from SurRender rendering

#### Correspondences
- **Not pre-computed**. Must be derived at training time from depth + intrinsics + poses (this is exactly what EfficientLoFTR's supervision module does)

| Key | Shape | Description |
|-----|-------|-------------|
| `image0` | `(1, H, W)` | Grayscale, float32, normalized [0,1] |

| `depth1` | `(H, W)` | float32, metric depth, 0 = invalid |

| `T_1to0` | `(4, 4)` | Relative pose: camera1 → camera0 |
| `K0` | `(3, 3)` | Intrinsics for image0 (at original resolution) |
| `K1` | `(3, 3)` | Intrinsics for image1 (at original resolution) |
| `scale0` | `(2,)` | `[w_orig/w_resized, h_orig/h_resized]` |
| `scale1` | `(2,)` | Same for image1 |

| `pair_names` | `(str, str)` | Pair identifier for logging |

**Optional keys** (when padding is used):
- `mask0`, `mask1`: `(H, W)` boolean masks for padded regions

#### How supervision is generated (runtime, no pre-computation)

The `_trainval_inference` method in `PL_LoFTR` (lightning_loftr.py L102-117) calls:

1. **`compute_supervision_coarse(batch, config)`** — calls `spvs_coarse()`:
   - Creates coarse-level grid points
   - Uses `warp_kpts()` to warp grid bidirectionally via `depth0`/`depth1`, `K0`/`K1`, `T_0to1`/`T_1to0`
   - Finds mutual nearest neighbors → `conf_matrix_gt [N, hw0, hw1]`
   - Outputs: `spv_b_ids`, `spv_i_ids`, `spv_j_ids`, `spv_w_pt0_i`, `spv_pt1_i`

2. **Forward pass through LoFTR model** → produces `conf_matrix`, coarse matches, fine features

3. **`compute_supervision_fine(batch, config)`** — calls `spvs_fine()`:
   - Uses coarse matches + depth warping to build fine-level GT
   - Outputs: `conf_matrix_f_gt`, `expec_f_gt`, `m_ids_f`, `i_ids_f`, `j_ids_f_di`, `j_ids_f_dj`

4. **`LoFTRLoss.forward(batch)`** — three loss terms:
   - **Coarse loss**: focal loss on `conf_matrix` vs `conf_matrix_gt`
   - **Fine loss**: focal loss on `conf_matrix_f` vs `conf_matrix_f_gt`
   - **Sub-pixel loss**: L2 on `expec_f` vs `expec_f_gt`

#### Critical geometry function: `warp_kpts` (geometry.py)

```
Input: kpts0 [N,L,2], depth0 [N,H,W], depth1 [N,H,W], T_0to1 [N,3,4], K0 [N,3,3], K1 [N,3,3]
Process: unproject → rigid transform → project → covisibility check → depth consistency check
Output: valid_mask [N,L], warped_kpts [N,L,2]
```

This function handles everything — the dataset just needs to supply correct depth maps, intrinsics, and relative poses.

### A3. StereoLunar → EfficientLoFTR Geometry Conversion

#### Pose conversion (critical)

StereoLunar stores `cam2world` (4×4). EfficientLoFTR expects relative `T_0to1` computed as:

```python
# MegaDepth convention (megadepth.py L100-103):
# T0, T1 are world-to-camera (w2c) poses
# T_0to1 = T1 @ inv(T0)  → transforms points from cam0 to cam1

# For StereoLunar:
# cam2world0, cam2world1 are camera-to-world (c2w)
# world2cam0 = inv(cam2world0)
# world2cam1 = inv(cam2world1)
# T_0to1 = world2cam1 @ cam2world0
T_0to1 = np.linalg.inv(cam2world1) @ cam2world0
T_1to0 = np.linalg.inv(T_0to1)
```

#### Depth handling
- StereoLunar EXR depth is already metric Z-buffer (same convention as MegaDepth/ScanNet)
- Need to: clean NaN/Inf → 0, clip extreme outliers, resize to match image resolution
- **No coordinate system conversion needed** — the depth is per-pixel distance along the optical axis

#### Intrinsics handling
- `K` in the batch should be at **original image resolution** (512×512)
- `scale0 = [w_orig/w_resized, h_orig/h_resized]`
- The supervision code (`spvs_coarse`, L55-56) handles the mapping: `scale0 = scale * data['scale0']`
- If images are not resized (512→512), then `scale0 = [1.0, 1.0]`
- Do NOT scale K in the dataset — keep it at original resolution

#### Image format
- StereoLunar: RGB JPEG → must convert to **grayscale** (EfficientLoFTR uses single-channel)
- Normalize to [0, 1], shape `(1, H, W)`

### Step 3: StereoLunar Dataset Class (Core Adapter) — CORRECTED

**File to create**: `src/datasets/stereo_lunar.py`

Model after: `EfficientLoFTR/src/datasets/megadepth.py` (134 lines) AND `StereoLunar/mast3r/dust3r/dust3r/datasets/LunarDataset.py`

```python
import os.path as osp
import numpy as np
import cv2
import torch
from torch.utils.data import Dataset


class StereoLunarDataset(Dataset):
    """
    Loads StereoLunar image pairs with depth and camera params
    in the exact format expected by EfficientLoFTR's training pipeline.

    IMPORTANT: Uses the OFFICIAL split from split.npz. The dataset internally
    splits training pairs 80/20 at the SCENE LEVEL (not pair level) to avoid
    terrain leakage. The 'val' split is a subset of training scenes.

    Constructor args:
        root_dir (str):    Path to StereoLunar dataset root containing scene dirs
        split_file (str):  Path to split.npz (official manifest from Zenodo)
        split (str):       'train' | 'val' | 'test' — 'val' carves 20% from train scenes
        img_resize (int):  Target image size (default 512)
        img_padding (bool): Whether to zero-pad to square
        depth_padding (bool): Whether to zero-pad depth
        augment_fn:        Optional augmentation function
        fp16 (bool):       Whether to use half precision
    """

    def __init__(self, root_dir, split_file, split='train',
                 img_resize=512, img_padding=False, depth_padding=False,
                 augment_fn=None, fp16=False, val_ratio=0.2, seed=42, **kwargs):
        super().__init__()
        self.root_dir = root_dir
        self.split = split
        self.img_resize = img_resize
        self.img_padding = img_padding
        self.fp16 = fp16
        self.augment_fn = augment_fn if split == 'train' else None
        self.val_ratio = val_ratio
        self.seed = seed

        # Load official split manifest
        data = np.load(split_file, allow_pickle=True)
        self.all_scenes = data['scenes']      # scene directory names
        self.all_images = data['images']      # image prefixes
        all_pairs = data['pairs']             # [scene_id, im1_id, im2_id, score]

        # Partition at the SCENE / TERRAIN level to prevent data leakage:
        # Multiple lighting setups and consecutive views share identical terrain within a scene.
        # Scenes must be strictly disjoint: Scenes(train) ∩ Scenes(val) ∩ Scenes(test) = ∅.
        if 'split' in data:
            # If the manifest provides explicit per-pair or per-scene split tags
            split_mask = (data['split'] == split)
            self.pairs = all_pairs[split_mask]
        else:
            unique_scene_ids = np.unique(all_pairs[:, 0])
            n_scenes = len(unique_scene_ids)

            # Deterministic disjoint scene assignment
            rng = np.random.RandomState(seed)
            shuffled_scenes = rng.permutation(unique_scene_ids)
            
            n_val = max(1, int(n_scenes * val_ratio))
            n_test = max(1, int(n_scenes * 0.15)) if n_scenes > 3 else 1
            
            val_scene_ids = set(shuffled_scenes[:n_val])
            test_scene_ids = set(shuffled_scenes[n_val:n_val + n_test])
            train_scene_ids = set(shuffled_scenes[n_val + n_test:])
            
            # For small test sets (e.g. 3 sample scenes), ensure train has at least 1 scene
            if len(train_scene_ids) == 0:
                train_scene_ids = set(shuffled_scenes[:max(1, n_scenes - 1)])
                val_scene_ids = set(shuffled_scenes[max(1, n_scenes - 1):])
                test_scene_ids = val_scene_ids

            if split == 'train':
                target_scenes = train_scene_ids
            elif split == 'val':
                target_scenes = val_scene_ids
            elif split == 'test':
                target_scenes = test_scene_ids
            else:
                target_scenes = set(unique_scene_ids)

            # Filter pairs so both frames belong strictly to target scenes
            self.pairs = [p for p in all_pairs if p[0] in target_scenes]

        self.pairs = np.array(self.pairs)

    def __len__(self):
        return len(self.pairs)

    def __getitem__(self, idx):
        scene_id, im1_id, im2_id, score = self.pairs[idx]
        scene = str(self.all_scenes[scene_id])
        seq_path = osp.join(self.root_dir, scene)

        img_name0 = str(self.all_images[im1_id])
        img_name1 = str(self.all_images[im2_id])

        # --- Read grayscale images ---
        image0 = cv2.imread(osp.join(seq_path, f"{img_name0}.jpg"), cv2.IMREAD_GRAYSCALE)
        image1 = cv2.imread(osp.join(seq_path, f"{img_name1}.jpg"), cv2.IMREAD_GRAYSCALE)

        # --- Read depth maps (EXR → float32) ---
        depth0 = self._read_depth(osp.join(seq_path, f"{img_name0}.exr"))
        depth1 = self._read_depth(osp.join(seq_path, f"{img_name1}.exr"))

        # --- Read camera params ---
        params0 = np.load(osp.join(seq_path, f"{img_name0}.npz"))
        params1 = np.load(osp.join(seq_path, f"{img_name1}.npz"))

        K0 = torch.tensor(params0['intrinsics'].copy(), dtype=torch.float32)  # (3, 3)
        K1 = torch.tensor(params1['intrinsics'].copy(), dtype=torch.float32)
        cam2world0 = params0['cam2world'].astype(np.float64)
        cam2world1 = params1['cam2world'].astype(np.float64)

        # --- Compute relative poses ---
        # T_0to1 = world2cam1 @ cam2world0 = inv(cam2world1) @ cam2world0
        T_0to1 = torch.tensor(
            np.linalg.inv(cam2world1) @ cam2world0,
            dtype=torch.float32
        )[:4, :4]
        T_1to0 = T_0to1.inverse()

        # --- Resize if needed ---
        h_orig, w_orig = image0.shape[:2]
        h_new = w_new = self.img_resize

        if h_new != h_orig or w_new != w_orig:
            image0 = cv2.resize(image0, (w_new, h_new))
            image1 = cv2.resize(image1, (w_new, h_new))
            depth0 = cv2.resize(depth0, (w_new, h_new), interpolation=cv2.INTER_NEAREST)
            depth1 = cv2.resize(depth1, (w_new, h_new), interpolation=cv2.INTER_NEAREST)

        # scale = [w_orig/w_new, h_orig/h_new] — maps resized coords to original
        scale0 = torch.tensor([w_orig / w_new, h_orig / h_new], dtype=torch.float32)
        scale1 = torch.tensor([w_orig / w_new, h_orig / h_new], dtype=torch.float32)

        # K stays at ORIGINAL resolution — supervision code uses scale to convert

        # --- Convert to tensors ---
        image0 = torch.from_numpy(image0).float()[None] / 255.0  # (1, H, W)
        image1 = torch.from_numpy(image1).float()[None] / 255.0
        depth0 = torch.from_numpy(depth0).float()                 # (H, W)
        depth1 = torch.from_numpy(depth1).float()

        if self.fp16:
            image0, image1 = image0.half(), image1.half()
            depth0, depth1 = depth0.half(), depth1.half()
            scale0, scale1 = scale0.half(), scale1.half()

        return {
            'image0': image0,
            'depth0': depth0,
            'image1': image1,
            'depth1': depth1,
            'T_0to1': T_0to1,
            'T_1to0': T_1to0,
            'K0': K0,
            'K1': K1,
            'scale0': scale0,
            'scale1': scale1,
            'dataset_name': 'StereoLunar',
            'scene_id': scene,
            'pair_id': idx,
            'pair_names': (f"{scene}/{img_name0}", f"{scene}/{img_name1}"),
        }

    def _read_depth(self, path):
        """Read EXR depth map as float32. Clean invalid values per LunarDataset convention."""
        depth = cv2.imread(path, cv2.IMREAD_UNCHANGED)
        if depth is None:
            raise FileNotFoundError(f"Cannot read depth: {path}")
        if depth.ndim == 3:
            depth = depth[:, :, 0]  # Take first channel if multi-channel
        depth = depth.astype(np.float32)
        # Clean invalid values — matches LunarDataset._get_views()
        depth[~np.isfinite(depth)] = 0.0
        depth[depth <= 0] = 0.0
        # Clip at 98th percentile of valid depths (prevents extreme outliers)
        valid = depth[depth > 0]
        if valid.size > 0:
            clip_val = np.percentile(valid, 98)
            depth[depth > clip_val] = 0.0
        return depth  # (H, W) float32
```

## Part D — Potential Issues & Flags

### 1. Depth scale magnitude

StereoLunar depths are ~30,000 meters (lunar orbital altitude). EfficientLoFTR's `warp_kpts` uses a **relative** depth consistency check:
```python
# geometry.py L51:
consistent_mask = ((w_kpts0_depth - w_kpts0_depth_computed) / w_kpts0_depth).abs() < 0.2
```
This is a 20% relative tolerance, so absolute magnitude doesn't matter. **OK.**

### 2. Homogeneous coordinates precision

With depths ~30,000 m, the 3D points in camera coordinates will have large magnitudes. In `warp_kpts`:
```python
kpts0_h = torch.cat([kpts0, torch.ones_like(...)], dim=-1) * kpts0_depth[..., None]
kpts0_cam = K0.inverse() @ kpts0_h.transpose(2, 1)
```
The product `kpts0 * 30000` could reach ~1.5e7. This is within float32 precision (~7 decimal digits). **Should be fine, but monitor for NaN.**

### 3. Mixed precision (fp16) risk

Half precision has max ~65,504. Values like `depth * pixel_coord ~ 30000 * 512 ~ 1.5e7` would overflow fp16. However, the supervision code is wrapped in `torch.autocast(enabled=False)` at lightning_loftr.py L104, so it runs in fp32. **OK.**

### 4. Image padding

MegaDepth uses padding because images have varying aspect ratios. StereoLunar is always 512×512. **Set `img_padding=False`** and omit `mask0`/`mask1` from the batch dict. The supervision code handles this case (lines 55-56, 67-69 check for `'mask0' in data`).

### 5. `TRAIN_PAD_NUM_GT_MIN`

Default is 200. With batch_size=1 on 512×512 images (coarse resolution 64×64 = 4096 cells), `train_coarse_percent=0.3` → `num_matches_train=1228`. Need `TRAIN_PAD_NUM_GT_MIN < 1228`. Set to 50 for safety.

### 6. NPE (Neural Positional Encoding)

EfficientLoFTR uses RoPE with NPE config `[832, 832, 832, 832]` for MegaDepth at 832 resolution. For StereoLunar at 512, set `NPE = [512, 512, 512, 512]`.

### 7. PL version lock

`pytorch-lightning==1.3.5` is old and **requires PyTorch 1.12.1 + CUDA 11.3**. It will NOT work with PyTorch 2.x. The official training environment (`environment_training.yaml`) pins this exact combination. **Use it exactly** — do not attempt to upgrade PyTorch or PL.

### 8. Disk space

With only 7.2 GB free, the full dataset won't fit. Options:
1. Free up disk space (need ~100+ GB for full dataset)
2. Use external storage
3. Start with `quick_testing/` subset (~50 MB)

### 9. `dataset_name` string matching

The dataset class returns `'StereoLunar'` but supervision checks `data_source.lower()`. Ensure the string matches: `'stereolunar'`. In the dataset class, use `'StereoLunar'` (mixed case) — the `.lower()` call in supervision.py handles it.

### 10. Augmentation

The current `build_augmentor` in augment.py raises `NotImplementedError` for any non-None method. For fine-tuning with augmentation, either:
- Fix the guard (`raise` comes before `if method == 'dark'` check at L43-44) 
- Or create a lunar-specific augmenter for illumination variation
